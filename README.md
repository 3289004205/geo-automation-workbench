# GEO 自动化工作台

基于 `product-cutout-price-card` Skill 的本地产品视觉工作台。上传产品素材和版式参考、统一粘贴文案、通过本机 Codex CLI 自动核对映射并 执行透明产品抠图与场景化卡片生成。

界面采用白色主色、顶部导航、浅蓝标签与圆角卡片。无需前端构建，无需安装 npm 依赖。

## 快速开始

运行环境：Node.js 22 或更高版本，以及已安装、已登录的 Codex CLI。

```bash
git clone https://github.com/3289004205/geo-automation-workbench.git
cd geo-automation-workbench
codex login
npm start
```

浏览器打开 http://localhost:4326 。Windows 用户也可以双击 `start.bat`。

网站会检测 Codex 安装和登录状态。页面能连接 CLI，不代表当前账号及执行环境一定提供图像生成、分割或 PSD 工具；实际能力不足时任务会显示未完成并保存具体日志。

抠图默认按正常展示精度处理：已有真实透明通道、主体完整且无大片背景的图片可以直接复用，少量白边不阻断排版。需要精修时在补充要求中注明；产品结构、标识和颜色仍须保持。素材库索引和质检报告会区分普通展示验收与精修验收。

## 功能

- 产品素材和版式参考独立上传，支持 PNG、JPG、WebP。
- 完整文案以粘贴文本为真值，不使用截图代替文案。
- 执行阶段自动核对产品与文案对应关系，并输出映射清单。
- 支持参考版式、跑步机梯队、三列双排跨缝标题和四宫格卖点上移。
- 画布预设、自定义尺寸及补充要求。
- 生成任务、六阶段进度条、详细阶段状态、实时日志、停止任务及补充信息后继续或重试。
- 历史成品预览和逐文件下载。
- 长期透明素材库与索引，同型号同版本唯一命中时复用。
- 仅在成品完成后，由用户明确确认再请求可编辑分层 PSD。

产品保真规则来自 `skill/SKILL.md`：保持原方向和结构，仅平移与等比缩放；场景必须围绕受保护产品联合生成，先通过物理摆放检查再进行确定性文字排版。

## 文案格式

每个产品一段，段落之间空一行。文件名 / SKU 与素材名称应保持可唯一识别，价格、单位和型号保留原文。

```text
素材文件名 / SKU：产品A.png
商品名称：产品A完整名称
卖点：静音运行
参数或详情：请填写真实参数
价格（如有）：¥2,999.00
购买建议（如有）：请填写真实建议

素材文件名 / SKU：产品B.jpg
商品名称：产品B完整名称
卖点：请填写真实卖点
参数或详情：请填写真实参数
价格（如有）：
购买建议（如有）：
```

网站不再设置独立的映射预检环节。执行阶段核对素材、完整文案与产品对应关系；存在歧义的项目等待补充信息。

## 文件结构

```text
server.mjs             本地 HTTP 服务与 Codex 任务调度
server.test.mjs        输入约束与接口测试
public/                页面、交互与品牌素材
skill/                 Skill 与场景、排版、PSD 和质检规则
library/product-cutouts/  本地长期透明素材库（运行时创建）
data/<任务ID>/          输入、Skill 快照、任务记录和输出（运行时创建）
```

任务目录中的主要交付物：

```text
output/product-cutouts/  真实透明产品 PNG
output/final-cards/      成品 PNG，以及按需生成的 PSD
output/mapping.csv       产品映射
output/qc-report.md      质检记录
```

任务数据、生成文件、透明产品素材库及 Skill 交接包附带的实拍/透明产品资产均未纳入开源仓库。首次使用的素材库为空，新素材通过质检后由任务写入。

## 配置

可通过环境变量设置 `PORT`（默认 `4326`）、`CODEX_BIN`（CLI 可执行文件的绝对路径）或 `CODEX_PYTHON`（用于排版及透明通道校验的 Python 路径）。Windows 的 `CODEX_BIN` 应指向 `codex.exe`，不使用 `.cmd` 启动器。

服务自动发现系统 PATH、Codex 桌面客户端和 npm 安装的 CLI。凭证由本机 Codex 管理，不需要在网页中填写 API Key，也不要把凭证提交到 Git。

如果任务出现 `helper_unknown_error: setup refresh had errors`，桌面版 `0.162.0-alpha.2` 在 Windows 上可能因正在使用的 Node 运行时文件无法更新 ACL 而初始化失败。可在项目目录安装经过验证的独立 CLI：

```powershell
npm install --prefix runtime/codex-cli --no-audit --no-fund @openai/codex@0.160.1
npm start
```

工作台优先使用 `CODEX_BIN`，其次使用上述项目本地 CLI，再查找 PATH 和桌面版本。独立 CLI 继续使用本机登录和沙箱配置，不修改桌面配置。`runtime/` 不提交到仓库。每次任务启动前会在 Windows 沙箱内实际读取输入、Skill、质检清单及素材库；预检失败时立即停止，并在准备阶段显示错误。

## 验证与限制

```bash
npm test
```

进度条按已完成阶段更新，阶段开始/完成通过实际执行事件回报；失败或停止不会自动补成 100%。PSD 使用独立的图层重建、重开验证与交付阶段。

测试覆盖进度事件与失败状态、文本来源与原方向约束、版式参数、文件名及尺寸验证、静态资源、素材库接口和来源校验。GitHub Actions 配置为 Node.js 22 / 24，Linux / Windows。

网站仅监听 `127.0.0.1`，校验 Host / Origin 并限制下载路径。生成任务使用本机 Codex 权限与登录信息，输入会发送给该 CLI 所配置的模型/工具服务。请只处理你有权使用的素材。

这是本机单用户工具，未提供公网认证、多租户隔离或云端任务队列，不适合直接代理至公网。GitHub Pages 只能托管静态页面，不能运行本项目的 Codex 后端。

后端校验必需文件与 PNG 透明格式，并依赖 Skill 执行像素级、文案及 PSD 重开检查；没有独立视觉质检引擎。实际生成流程应在你的工具环境中验证，尤其是图像编辑、物理落地和可编辑 PSD。PSD 工具不可用或未通过检查时，不提供伪分层文件。
